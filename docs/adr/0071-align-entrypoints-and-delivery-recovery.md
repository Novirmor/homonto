# Align entrypoints and delivery recovery

- **Status:** Accepted
- **Date:** 2026-10-26

## Context

Commands repeated policy that had changed in skills: standalone h continuation
still selected engines, no resolution lacked delivery instructions, and to
discovery missed archived work awaiting publication. Review scope protections
were onto-specific despite the same repair-loop risks in to.

## Decision

Commands defer execution policy to their skills. Keep no's informational skill
and two workers, with one parent execution reference shared by `/no` and h
resolve. Engine-free delivery retains candidate and destination evidence in the
session/handoff rather than inventing lifecycle records. Direct h isolation may
use an explicitly chosen, identity-checked checkout without installing an engine.

To discovers matching archives before new work and resumes missing delivery;
archival never asserts remote readiness. Share evidence-based finding triage and
bounded rechecks across engines while preserving native evidence gates. Reuse
user-selected task isolation and keep commits parent-owned throughout.

Remove the catalog's placeholder command; projection tests use a real shipped
command instead. Explicit configurations referencing `builtin:example-command`
must remove or replace that declaration.

## Consequences

Entry paths share policy owners, reducing contradictory instructions. Engine-free
recovery depends on retained session/handoff evidence; lost evidence requires
investigation and re-verification. Prompt tests can detect known contradictions
and CLI tests prove local recovery sequences, but neither proves model compliance
or live GitHub readiness.
